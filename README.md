# Автоматизация тестирования «Калькулятора смет» на платформе TestQuest

Данный репозиторий содержит комплект автоматизированных тестов для проверки сквозного цикла работы «Калькулятора смет» на стенде платформы TestQuest. 

Проект разработан в рамках тестового задания. В соответствии с требованиями ТЗ, проектирование сценариев и базовая реализация автотестов (7 из 10 кейсов) выполнены с привлечением инструментов на базе **ИИ**. Основной упор сделан на сквозную логику перерасчета, валидацию полей ввода и верификацию структуры выгружаемого файла Excel.

---

## 🛠️ Стек технологий и архитектура
*   **Язык программирования:** Python 3.10+
*   **Фреймворк тестирования:** Pytest (тест-раннер, фикстуры)
*   **Автоматизация UI:** Playwright (библиотека `pytest-playwright` для быстрой и стабильной работы с браузером в Headless-режиме)
*   **Анализ файлов:** Openpyxl (для программного парсинга и валидации структуры скачанных `.xlsx` отчетов)

---

## 📋 Спроектированные и реализованные тест-кейсы

Ниже представлен перечень из 10 тест-кейсов. Каждый кейс имеет сквозную прослеживаемость (traceability) и напрямую сопоставлен с функцией в коде `tests/test_calculator.py`.

### Блок 1: Интерфейс и логика тарифов (Спроектировано ИИ)
*   **Тест-кейс №1: Проверка отображения элементов управления калькулятора** (`test_01_ui_elements_visibility`)
    *   *Предусловие:* Открыта главная страница калькулятора.
    *   *Шаги:* Проверить визуальное наличие полей: выбор тарифа, ввод пользователей, срок лицензии, чекбоксы модулей, кнопка «Выгрузить Excel».
    *   *Ожидаемый результат (ОР):* Все базовые элементы интерфейса отображаются и доступны для взаимодействия.
*   **Тест-кейс №2: Выбор тарифа «Облако» и «Коробка»** (`test_02_tariff_selection`)
    *   *Предусловие:* Калькулятор находится в базовом состоянии.
    *   *Шаги:* 1. Выбрать в выпадающем списке тариф «Облако». 2. Выбрать тариф «Коробка».
    *   *ОР:* При смене тарифа динамически меняются метки стоимости и логика доступных опций.

### Блок 2: Опции сметы и T&M (Спроектировано ИИ)
*   **Тест-кейс №3: Включение опции «Мета-КП»** (`test_07_meta_kp_toggle`)
    *   *Предусловие:* Выбран любой тариф.
    *   *Шаги:* Активировать чекбокс/переключатель «Мета-КП».
    *   *ОР:* В интерфейсе появляется дополнительный блок настроек или меняется структура отображения итоговой стоимости под формат Мета-КП.
*   **Тест-кейс №4: Добавление модулей и Внедрения** (`test_05_modules_activation_recalc`)
    *   *Предусловие:* Заданы базовые параметры (Тариф, Количество пользователей).
    *   *Шаги:* Отметить чекбоксы дополнительных модулей и блок «Внедрение».
    *   *ОР:* Сумма в блоке «ИТОГО» динамически увеличивается на стоимость выбранных модулей и услуг внедрения.
*   **Тест-кейс №5: Расчет работ по модели T&M (Time & Materials)** (`test_06_tm_hours_calculation`)
    *   *Предусловие:* Калькулятор открыт.
    *   *Шаги:* В поле часов T&M ввести числовое значение (например, `10` или `20`).
    *   *ОР:* В блоке детализации стоимости появляется строка с расчетом T&M, итоговая сумма увеличивается на расчетную величину.

### Блок 3: Валидация полей ввода (Спроектировано ИИ)
*   **Тест-кейс №6: Валидация поля «Количество пользователей»** (`test_03_validation_negative_users`)
    *   *Предусловие:* Выбран тариф «Облако».
    *   *Шаги:* Ввести в поле пользователей отрицательное значение (например, `-5`).
    *   *ОР:* Система блокирует отправку, выдает ошибку валидации «Некорректное число» либо автоматически сбрасывает значение до минимально допустимого.
*   **Тест-кейс №7: Валидация поля «Срок лицензии»** (`test_04_validation_max_license_term`)
    *   *Предусловие:* Выбран тариф «Коробка».
    *   *Шаги:* Ввести в поле срока аномально большое значение (например, `999` месяцев).
    *   *ОР:* Срабатывает ограничение максимального срока, выводится предупреждение валидации или значение корректируется.

### Блок 4: Сквозные сценарии и работа с Excel (Финальные бизнес-проверки)
*   **Тест-кейс №8: Сквозной расчет «ИТОГО» для комплексного заказа** (`test_08_full_cycle_calculation`)
    *   *Предусловие:* Очищены все поля.
    *   *Шаги:* Включить «Мета-КП» + Выбрать «Коробка» + Ввести 50 пользователей + Ввести 12 месяцев + Выбрать модули + Включить «Внедрение» + Задать часы T&M.
    *   *ОР:* Блок «ИТОГО» успешно рассчитывает финальную сумму без ошибок, значение калькулятора валидно (> 0).
*   **Тест-кейс №9: Выгрузка сметы в Excel** (`test_09_excel_export_download`)
    *   *Предусловие:* Выполнен расчет из Кейса №8.
    *   *Шаги:* Нажать на кнопку «Выгрузить Excel» (или аналогичную кнопку экспорта).
    *   *ОР:* Файл успешно скачивается на устройство, имеет расширение `.xlsx` и корректное имя.
*   **Тест-кейс №10: Валидация структуры скачанного файла Excel** (`test_10_excel_content_validation`)
    *   *Предусловие:* Файл Excel из Кейса №9 успешно сохранен в локальную директорию.
    *   *Шаги:* Открыть файл программно с помощью библиотеки `openpyxl`, проверить структуру страниц и наличие ключевых ячеек (Наименование тарифа, Итоговая сумма).
    *   *ОР:* Структура документа соответствует шаблону, файл содержит непустые строки с данными по сметным позициям.

## 🚀 Инструкция по запуску

Скрипты автоматизации настроены так, чтобы работать «из коробки» на чистой системе. Они самостоятельно создают изолированное виртуальное окружение, обновляют пакетный менеджер, устанавливают зависимости и скачивают бинарные файлы браузера Chromium для Playwright.

### 💻 Локальный запуск на Windows
В корневой папке проекта дважды кликните по файлу:
```bash
run-tests.bat
```
Файл выполнит все шаги настройки и запустит тесты в консоли. По окончании прогона консоль останется открытой для ознакомления с логами.

### 🐳 Запуск в автоматической песочнице (Linux / CI)
Для запуска тестов внутри проверочной песочницы используется bash-скрипт. Скрипт принимает переменную окружения `BASE_URL` для гибкой смены целевого стенда.

Команда для выполнения в терминале:
```bash
BASE_URL=https://pryaniki.com ./run-tests.sh
```

### ⏱️ Ограничения и тайм-ауты
*   Тесты оптимизированы по скорости и легко укладываются в критический лимит песочницы (**3 минуты**).
*   Скрипты корректно возвращают системный `exit code` (0 при успехе, 1 при падении тестов), выводя в финальный лог явный маркер **PASSED** или **FAILED**.
